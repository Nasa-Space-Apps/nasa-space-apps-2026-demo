# Project: Left Behind (Next.js + three.js)

A **game of stories** about the robotic explorers NASA left on Mars and the Moon, for NASA Space Apps 2026. It has two modes — **Story** (implemented) and **Decisions** (designed, **not implemented: do not build it unless the user asks**) — and two parts: **Part 1 "Earth"** (a 2D comic with a voice, until landing) and **Part 2 "Mars"/"Moon"** (the 3D with real checkpoints). **Six vehicles have a complete Story mode**: Opportunity, Spirit, Ingenuity, Surveyor 3, InSight and Beagle 2 (20 real events each; 120 narrations; 120 illustrations). Perseverance and SEV are "coming soon" (their 3D does not open). The globe is the menu before the game; `/` is the cover.

Before any product task read `docs/game-design.md`; before touching code read **`docs/README.md`** (the index) and **`docs/architecture.md`**. For style or vehicle work, `docs/design.md` and `docs/themes-and-missions.md`. This Next.js version has breaking changes: see `AGENTS.md`.

## Conventions

- **The user writes in Spanish: reply in Spanish.** Code and identifiers in English. The game's interface, texts and audio are in **English**. All repository documentation is in **English** (research data — dossiers, prompts, story-viewer content — is Spanish on purpose).
- **Commits:** conventional messages, **no AI attribution**, and **only when the user asks**; the user decides when to commit and push. Never read or print `.env.local` (it holds `ELEVENLABS_API_KEY` and `REPLICATE_API_KEY`; only the generator scripts use them).
- **Shared scene ⇄ DOM state:** `src/lib/game.ts` (a mutable object, no re-renders). Do not turn it into React state. The imperative mutation inside `useFrame` is intentional; the `react-hooks/immutability` rule is disabled on purpose (`eslint.config.mjs`).
- **Data** of terrain/vehicle goes in `src/lib/missions.ts`; **design tokens** only in `src/lib/themes.ts`, never hard-coded in components.
- **Before calling anything done:** `npx tsc --noEmit` and `npm run lint`. To see it in the browser, see `docs/gotchas.md`.
- **UI design:** a single theme, **"Ink & Paper" (comic; reference ponpon-mania.com/chapter/2) + flat design — a mandatory rule of the whole demo** (cream paper with a thick ink stroke, **a field and an accent per world** — terracotta + butter on Mars, steel blue + mint on the Moon, periwinkle + pink on the home —, pills, Libre Franklin 800/700 lowercase; no shadows, glows or gradients except the static grain; smooth motion always). Read `docs/design.md` before touching UI. Tokens live **only** in `src/lib/themes.ts` (`BASE` + `WORLDS`; `themeFor(world)` and the `useTheme()` hook; published as CSS variables by `WorldVars`); shared DOM styles in `src/lib/ui.ts` and the `.ui-*` classes of `globals.css`. Every transition uses `THEME.ease`/`dur`; no loose colours or curves. Icons only from `components/Icon.tsx` (no glyphs like → ▶ ■); buttons use the `.ui-btn`/`.ui-link` classes. Use `useTheme()` in UI components (do not import `THEME` directly). There is no theme selector and no `1…9` shortcuts. New `@keyframes` in `globals.css` are not picked up in dev: use inline transitions (`ease()` from `lib/ui.ts`, `Reveal`).
- **Loading:** nothing appears abruptly. One loading screen in `components/Loading.tsx` (route fallbacks, chunks and the scene, which waits for `game.terrain`); exits fade **before** navigating and canvases/photos enter with a fade (`FadeImg`, `onCreated`). Details in `docs/design.md` ("Loading").
- **Performance:** `src/lib/perf.ts` holds a profile (`light` by default / `full`) that caps `dpr` (1.5), removes the scene's antialiasing, drops the stopped scene to 30 fps and frees the canvas of views that are not the current route. Do not put `dpr`/`antialias` loose on a `Canvas`: use `PERF`. To roll back: `PERF_PROFILE = "full"`. See `docs/performance.md`.
- **Responsive:** every view must work on phone, sideways phone and tablet as well as desktop. Use `useViewport()` (`lib/viewport.ts`: `compact`/`phone`/`short`) to decide which HUD to mount, and CSS (`clamp`, `dvh`, `env(safe-area-inset-*)`) for the rest; `TouchControls` replace the keys; touch targets ≥ 44 px (`.ui-hit` for small ones). What is hidden on mobile and why: `docs/design.md` ("Responsive").
- **Stationary vehicles** (InSight, Beagle 2, Surveyor 3): the module never moved, so in 3D it is **not driven**: it stays put (`STATIONARY` + `BASE` in `scripts/data/<mission>-story.mjs`; `story.json` carries `stationary: true`) and **Space** (or a timeline click) goes to the **next moment** of the story: another card, another narration, and the camera steps around the module. Technical detail: `docs/architecture.md` ("Stationary vehicles").
- **Information audit:** everything the user sees must be **real and verified**; what cannot be resolved gets a default value and a documented `TODO(audit)` in `docs/audit.md`. Before accepting a new story or a data change: `npm run story-audit -- <mission>` (numbers and months against the dossier), `npm run story-audio -- <mission> --dry-run` (audio up to date) and a contact sheet of the illustrations.
- **Vehicles are procedural** (3 tones of one colour, no GLBs, in the style of `docs/design.md#vehicles`): do not apply style layers to imported models. One file per vehicle in `src/lib/vehicles/<id>.ts`, drawn with the kit of `src/lib/vehicles/kit.ts` (everything is merged into 1 mesh + 1 per wheel: do not create loose meshes), with proportions measured on the reference GLB. `src/lib/vehicles.ts` only exposes `buildVehicle`. Terrains (STL) live in `public/models` and are documented in `docs/assets.md`.
- **Vehicles without a story** (`sev`, `perseverance`): they appear on the globe with "coming soon" and their 3D does not open (`storyOf(id)` is `undefined`; `/<world>/<id>` redirects to the globe). Their procedural model and `missions.ts` entry are kept (with `checkpoints: []`). To open one: give it a story (`docs/story.md`). When adding another vehicle follow the recipe of `docs/themes-and-missions.md` (`scripts/generate-guide.mjs` and `lib/guide-lines.ts` also know vehicles by id).
- **Stories:** the checkpoints/texts of the storytelling come from each mission's `public/models/<mission>/story.json` (`src/lib/story.ts`; copy in `scripts/data/<mission>-story.mjs`), not from components; `src/lib/checkpoints.ts` only defines the `Checkpoint` type. Recipe for another mission: `docs/story.md`. The illustrations are the mission's (`public/models/<mission>/images`).
- **Narration (ElevenLabs):** audio is **pre-recorded** per mission in `public/models/<mission>/audio` with `npm run story-audio -- <mission>`; the app calls no API at run time. If you change a `narration` in `scripts/data/<mission>-story.mjs`, regenerate (`npm run story`) and re-record the clip. **Method fixed by the user:** only the audio is requested from ElevenLabs and the timings are computed on the client (`lib/transcript.ts`, the real duration spread by characters): for new audio record only the audio and the subtitle works by itself. Do not ask ElevenLabs for timestamps. Everything a voice says has a subtitle (`Captions.tsx`). Recipe in `docs/narration.md`.
- **Voice guide:** phrases in `src/lib/guide-lines.ts` (no imports; Node loads it too; only generic ones and Opportunity's), pre-recorded audio with `npm run guide`; the catalogue in `docs/guide.md` is regenerated with `npm run guide -- --docs`. Sparse and contextual: respect the anti-saturation rules of `docs/guide.md` when adding categories.
- **Background music:** 3 beds pre-recorded with ElevenLabs Music (`npm run ambient`, prompts in `src/lib/ambient-tracks.ts`, audio in `public/ambient`), played by `lib/ambient.ts` (`<Ambient track=…/>`): a loop with crossfade that drops to 20 % while narration or guide plays, key `S`. See `docs/ambient.md`.
- **Routes:** `/` is the **home** (one composition with illustration cards and Opportunity in 3D, its own palette — world `home`; see `docs/design.md` "Home"); `/[body]` is the globe (`Explore`) and `/[body]/[vehicle]` the story (`Journey` → `Scene`; the slug is the mission id). Each view is loaded by its loader (`ExploreLoader`/`SceneLoader`/`HomeLoader`, `ssr: false`): do not import the scene from the globe or vice versa. `cacheComponents` is on: `await params` goes inside a `<Suspense>`. See "Routes and views" in `docs/architecture.md`.
- **Globe:** a light wireframe style with `theme.globe` tokens; **no textures or assets**; an **orthographic camera** (isometric look at the start); it **turns on two axes** (its own and the pitch, **no roll**, with inertia) but **with a limit while steering by hand** (the visible face always has a vehicle: see `Globe.tsx`, `MAX_OFF`/`SNAP_OFF`) **and on release the pitch returns to the initial lean** (the longitude is kept); it spins by itself without limit and only the front is drawn. **The zoom** (wheel, Ctrl+wheel/pinch and Ctrl +/−/0) is done by the camera: it scales only the globe and the vehicles, never the DOM buttons, labels or cards; it has limits (0.75–2.6) that also tighten the rotation limit when zooming in (`maxOff()`). It is the **menu before the game**: no panel or list; a floating control changes world; each abandoned site has its vehicle **sunk into a mass that glues it to the ground, symbiote-like** (`lib/vehicles/mini.ts` gives the exaggerated shape and `blob.ts` tilts and melts it into one mesh; ink + accent + paper; it turns to face the viewer) and its card (`VehicleCard` → `VehicleView` over a plain background) **floats beside it** (`placeFloating` in `GlobeLabels.tsx`, imperative). Do not use drei's `Html` (DOM labels are in `GlobeLabels.tsx`).
- **Credits (visible):** the "Credits" button top right of the globe and the home, with the "created by" card (`components/Credits.tsx`), and a "created by" line on every story's closing card (`CreatedBy`). People in `src/lib/team.ts` (Jackson Merma, AI & Software Engineer; Paul Luque, Full Stack Developer; each with a LinkedIn link) and their flat portraits in `public/team/<id>.jpg` (4:5, ~720 px). To add someone: an entry in `TEAM` and their photo.
- **Tab icon:** the rover's camera mast, in `src/app/favicon.ico`, `icon.svg` and `apple-icon.png` (Next picks them up by file convention).
- **Pitch video:** a 30-second Remotion video lives locally in `video/` (git-ignored): the documentation of how it was built and re-generated is `video/plan.md`; it reuses the app's own code (`@/…` aliases into `src/`).

## Research pipeline (apart from the web demo)

To turn a mission into a verified story of N events use the skill `mars-mission-story-pipeline` (`.claude/skills/`). Outputs always go to `misiones/<id>/` (never mixed between missions); tools in `agents/opportunity-research/pipeline.py`. Start with `pipeline.py estado <id>`. **Before researching events, ask for N and wait for the answer.** `agents/` and `story/` belong to the team: read them, do not modify them. The whole flow, rules, costs and lessons: **`docs/research-pipeline.md`** (read it once before working on the pipeline).
