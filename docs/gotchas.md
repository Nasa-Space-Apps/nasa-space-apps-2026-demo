# Gotchas and problems already solved

## Next.js 16

- `AGENTS.md` (generated by Next) warns that this version changes APIs. Read `node_modules/next/dist/docs/` before using Next APIs you do not know. `layout.tsx` uses the global type `LayoutProps<"/">`.
- `ssr: false` in `next/dynamic` only works inside a Client Component → that is why `SceneLoader.tsx`, `ExploreLoader.tsx` and `HomeLoader.tsx` exist.
- **`cacheComponents` is on** (`next.config.ts`): `await params` outside `<Suspense>` gives "instant shell"; see "Routes and views" in [architecture.md](architecture.md). Invalid routes return 200 with the 404 page (the `notFound()` happens inside the Suspense, already streaming).
- `next dev` shows an "N" indicator bottom left (development only). The key chips are centred at the bottom so as not to overlap it.
- **After merges or branch changes the UI can look "broken"** (buttons in uppercase and mono, an unstyled world selector) although the code is right: the dev server (Turbopack) keeps serving an **old** stylesheet from its cache `.next/dev/cache`; neither `touch globals.css` nor reloading fixes it. Check: in the console, `fetch(document.styleSheets[0].href).then(r=>r.text()).then(t=>t.includes('.ui-world'))` must give `true`. **Fix:** stop `npm run dev`, delete the `.next` folder (`Remove-Item -Recurse -Force .next`), start again and reload with Ctrl+Shift+R. It is not a bug of any commit. The same happened with the new `.home-*` classes of the home page.
- New `@keyframes` in `globals.css` are not picked up by the dev server (the bundle did not include them even after reloading): use inline transitions (`ease()` from `lib/ui.ts`, `Reveal`), the Web Animations API for loops (`el.animate`, see `VehicleCard`; cancel it on unmount) and springs in `lib/motion.ts` for 3D. New CSS may also need a page reload (`location.reload()`) before it reaches the dev bundle: check with `document.styleSheets` before debugging code.
- **The dev server is started by the owner** (who asked not to leave any running). If you start one to test, close it afterwards. Next warns if one already exists in the project ("You can access the existing server at…") and does not start a second: test against the existing one.
- `rm -rf .next` with the dev server running is safe (it regenerates); `.next/types` can go stale if you delete a route: `npx next typegen` regenerates it.

## ESLint / React Compiler

- The rule `react-hooks/immutability` flagged mutation inside `useFrame` (positions, `game.*`, buffers) as an error. It is a false positive for imperative R3F code → **disabled** in `eslint.config.mjs`.
- Do not assign `game.*` during render (the rule saw it as an error); do it in `useEffect` or `useFrame`.

## three.js / R3F

- **Harmless console warnings:** `THREE.Clock deprecated` and `PCFSoftShadowMap has been removed` come from R3F/three, not from the project's code.
- **STL is Z-up:** if something comes out lying down, it is the `rotateX(-90°)` in `buildTerrain`.
- **Black models:** does not apply to the vehicles (their 3-tone `ShaderMaterial` uses no PBR lighting). A GLB with high `metalness` and no environment map would come out black.
- **Terrain borders:** they are flattened + an infinite ground plane + fog. On steep terrains the border is a strong slope: do not put stops near it.
- **Mission change:** `Experience` remounts with `key={mission.id}`; the rover's state (`st`) and the tracks reset on their own, `game` resets in the `useEffect`. The minimap detects the change by comparing `game.terrain`.
- **Inside R3F's `<Canvas>` the React context does not arrive** (`usePathname`, `useTheme`…): `Experience` (`Scene.tsx`) takes the theme with `themeFor(bodyOfMission(mission.id).id)`; the globe receives `theme` by props. Do not use `useTheme()` in canvas components.
- **A `Canvas` inside an element with `transform: scale`** (e.g. inside `Pop`) is measured with `getBoundingClientRect`, which includes the scale: halfway through the pop the canvas "measures" little and the vehicle ends up tiny. Use `resize={{ offsetSize: true }}` (layout measure, no transforms), as `VehicleView` does.
- **R3F in `frameloop="demand"`:** invalidating only from outside the render (your own `requestAnimationFrame`) gives **one frame in two** (30 fps even if you ask for 60). To sustain 60 fps, invalidate from inside `useFrame` (`FrameGovernor`). Count frames with `drawElements`, not `requestAnimationFrame`.
- `VehicleView` uses `frameloop="demand"`: if you change the model or the camera, call `invalidate()` (the framing effect already does).
- **Vehicles (kit):** in `Kit.loft` the order of the rings decides where the surface faces; the material is double-sided, so an inside-out hull does not vanish, but if everything comes out dark the normals point inwards. Do not use negative scales to mirror parts (they flip the faces): mirror the coordinates (`for (const s of [-1, 1])`). The left wheels are drawn turned 180°, so in `wheel()` the outer face is always +x.
- **Testing a vehicle without a browser:** the models import nothing from Next and do not use the `@/` alias, so Node can build them (`buildVehicle`) and dump their triangles; keep those files free of app imports.
- **The globe uses an orthographic camera:** the shaders of `Globe.tsx` (grid, orbiting squares) and the `front` of `Pin` assume a constant view direction (+z in view). If you go back to perspective, the direction to the camera per vertex must be recovered. The zoom (pixels per unit) is set by `Fit` with `frame()` × the user's zoom (`view.cur`).
- **No `Html` from drei in the `Canvas`** (labels): in development with StrictMode it raises "Attempted to synchronously unmount a root while React was already rendering" and loses labels. Own DOM labels (`GlobeLabels.tsx`) positioned by projection are used.

## Scale and terrain

- **The vehicles are not to scale** (see "Unresolved: real scale" in [roadmap.md](roadmap.md)). The STLs are not metres either: do not deduce real distances from the units.
- **The centre of the maps is a crater** (the landing point). On Mars (Opportunity) its walls are very steep: a vehicle placed there leans almost vertical. It comes from the exaggerated relief, not from a physics bug.
- **Gale terrain** (`gale-terrain.stl`): a huge central mound with 30–40° slopes (the route planner cannot make a smooth path over it) and a flat crater floor at z ≈ 0 with 20–30 high walls. Flat ground is on the north and east plateaus; the crater floor is the flat stand-in for Beagle 2. Before choosing `ANCHORS` print a height/slope map with `scripts/lib/terrain-node.mjs` (`loadTerrain` → `heightAt`, `slopeAt`); the first and last anchors are not snapped to flat ground: place them yourself on a plain. Spirit uses Meridiani for that reason.

## Checkpoints

- **Never put a checkpoint where the vehicle starts** (Mars (0, 0)): it would activate on load. The coordinates are **world** coordinates (terrain centred). If the STL is Z-up: `X = x − cx`, `Z = −(y − cy)`.
- The vehicle stops by itself at the centre of every checkpoint (with `Space`), so the card shows as long as you want. On an automatic trip the intermediate checkpoints are crossed without card or narration.
- **The start is already active on load** (the vehicle appears inside its radius): its card and narration start by themselves. The browser blocks audio without a prior gesture → you see "Browser blocked audio: press Listen" until there is a click or key; the button solves it.
- **A leg's goal is not recomputed while braking** (`st.goal` in `Rover.tsx`): if "the next stop > s + 0.5" were searched every frame, being < 0.5 u from the checkpoint would jump to the next and the vehicle would not stop (a real bug that was fixed).
- With `game.stationary`, `game.s` is a time cursor, not a distance; do not use `game.x/z` or proximity to know which moment you are on (use `game.active` or `route.stops`). Space calls `stepForward()`, it does not set `input.go`; in tests one press = one moment. The model **cannot have wheels** (`rig.wheels` empty, and `halfLen/halfWid` must be passed to `finish()`: they come from the wheels).
- The card is bottom left. `visited` is not persisted: it resets on reload.
- **Voice guide**: times are real clock, movement is simulation time (`dt` ≤ 0.05 s): at low fps the guide seems "ahead" of the vehicle. To test it, hook `HTMLMediaElement.prototype.play` and log `src` + `performance.now()`; the subtitle is in the `[aria-live]` of the captions. See [guide.md](guide.md).
- If the browser runs at ~1 fps (another tab with the scene open competes for the GPU), the vehicle hardly advances: `dt` is capped at 0.05 s per frame. When testing with automation, drive by position (reading the minimap), not by time.

## Keyboard and focus

- A **`background` inline style cancels the sweep** of `.ui-btn`/`.ui-nav`/`.ui-row` (the shorthand clears `background-image`): in the top bar that left the text of "Globe" ink on ink on hover. Do not put an inline `background` on elements with those classes (use the class or `backgroundColor` only if you do not need the sweep).
- After pressing a DOM button, `Space` (advance) could re-activate it → the selectors, the Listen button and the timeline markers call `blur()` on click.
- The keyboard listeners are on `window`; `bindKeyboard()` calls `preventDefault` only for the game's keys.
- **`position: relative` in a class of your own overrides Tailwind's `absolute`** (utilities go in a layer and CSS without a layer wins): `.ui-hit` must not set `position`; the timeline markers were misplaced for that reason.
- A container with `justify-content: center` and overflow **cuts off the start** (the comic's closing card on a phone): use `safe center`.
- Cards anchored to the right of their button (`Credits`) overflow on the left when the button is not at the edge: on compact screens they are `fixed` and edge to edge.

## Testing in the browser (method used)

With the Claude in Chrome extension (or any browser):

1. `npm run dev` and open `http://localhost:3000`.
2. The synthetic key presses of a "key" tool are too short to drive. Instead, dispatch events from the console:
   ```js
   const k=(c,d)=>window.dispatchEvent(new KeyboardEvent(d?'keydown':'keyup',{code:c,bubbles:true}));
   k('Space',1);                      // advance
   setTimeout(()=>k('Space',0), 2000);
   ```
   (`Space` advances to the next checkpoint and stops by itself; `KeyN` narration, `KeyG` guide.) To jump to a checkpoint without waiting: `document.querySelectorAll('[aria-label="Route timeline"] button')[i].click()`. Read "Pos X · Z" from the minimap and the status text of the timeline (`span.truncate`) to check where you are. For audio to play you need **a real click** first (synthetic events do not count as a user gesture).
3. Go straight to a vehicle: `http://localhost:3000/mars/opportunity`; to the globe with a card: `/mars#opportunity`. To silence: `localStorage.setItem('poc-narration','off')` (`poc-narration` / `poc-guide`: `on|off`) — these are the owner's real preferences if you use their browser: restore them.
4. Console errors can be **stale** (intermediate HMR states while editing); reload and read again.
5. **"The narration is not heard" ≠ broken audio:** the cause was `localStorage['poc-narration'] = "off"` (the `N` key). The mp3s were valid (duration and volume were compared with `ffprobe`/`ffmpeg volumedetect`). Check the preference before re-recording anything (it costs credits); press `N` until you see "narration on" and reload.
6. `computer.wait` allows at most 10 s; `zoom` requires a region inside the viewport. The "skip to mars" button position depends on the viewport width: look at the screenshot before clicking. The narration does play in the test browser (the audio is real). `left_click_drag` on the globe releases within the same action, so the next capture already shows the globe straightened up.
7. **Testing a screen size:** see "Responsive" in [design.md](design.md#responsive) (the iframe method; reloading many WebGL iframes kills the tab).

## Going back to the globe or the home (Next keeps views alive)

- With `cacheComponents`, Next **keeps the previous view mounted** (hidden, with its React state) when you navigate to another route, and **re-runs its effects** when you come back. `Explore` faded to white when travelling (`leaving = true`) and on coming back with "← Globe" or the browser's Back it stayed so: a blank page at `/mars#opportunity`. Fixed by resetting `leaving` in the mount effect. **Rule:** all transient state of a view (fades, "in progress"…) must be reset in the mount effect, not in the `useState` initialiser. To reproduce: `/mars` → click the vehicle → Travel to the past → `navigate back`.
- **The home had the same bug:** "start" faded the page to the field colour and, on returning with the globe's logo, **the home came out blank** because Next had kept it hidden with that fade. Fixed with the same rule: `Home` renders nothing when the route is not `/` (the `light` perf profile also releases its 3D canvas and it mounts again from scratch, with its entrance) and its mount effect resets `leaving` (the `full` profile). To reproduce: `/` → "start" → click the globe's logo. (A programmatic click on the logo worked at first: the bug only shows if the home was already visited.)
- **Performance:** for the same reason every visited view stayed mounted (≈ +350–400 MB of GPU per scene). `Scene` and `Explore` now render nothing when their route is not the current one (`usePathname`), see [performance.md](performance.md). `PERF.releaseHiddenViews = false` disables it.
- Click outside the card (`Explore`) ignores the click that opened it with a timestamp (`openedAt`): the effect that registers the listener can run before that same click reaches `window`.

## Audio: do not trust `preload`

- A `new Audio(url)` that is not in the DOM can lose its buffer over time and re-request the file when played (seconds of "Loading…" with no subtitles). The narration clips are kept as **Blobs in memory** (`loadNarration` in `lib/narration.ts`): if you add another audio that must play without delay, do the same and preload it before the user gets there (as `useStoryAssets` does in `Journey`).
- `Captions` and the narration: the bubble turns itself off when the clip ends (`ended`) or on stopping (`stopNarration`). If you edit a checkpoint's `narration`, the subtitles recompute by themselves when the audio is re-recorded (there are no timing files to maintain). The subtitle and the chip update when the audio **starts playing**: if an mp3 is missing, the phrase is skipped silently.
- If you edit `narration` (the script) of a story you must re-record the audio (`npm run story-audio -- <mission>`); otherwise the mp3 says something else (`--dry-run` marks it `changed`).

## Mounting the 3D scene blocks the thread

- Building the terrain (`buildTerrain`, height map, minimap) and compiling the shaders (`<Preload all/>`) blocks the main thread **~6 s in development** (measured with `PerformanceObserver` `longtask`): meanwhile buttons, keys and subtitles do not answer. **Do not mount `Scene` behind something interactive**: do it when the user is already waiting for a load (e.g. on landing from the comic) and cover it with transform/opacity transitions, which stay on the compositor. To advance network-only work, a `fetch` of the STL is enough.
- Measure like this: in the console, `new PerformanceObserver(l => l.getEntries().forEach(e => console.log(e.startTime|0, e.duration|0))).observe({entryTypes:['longtask']})` and turn the page.

## Globe notes

- **Turntable (milestone 51):** the state is `(pitch, spin)` and the orientation `Rx(pitch)·Ry(spin)` (no roll). The centre of the screen in the globe's frame is **latitude = pitch, longitude = −spin − 90°** (`lonOf`, the inverse of `faceAngle`), so the vehicle limit, the snap and the straightening are computed on that point (`look`/`toward`/`constrain`) and converted back to `(pitch, spin)` with `asin(y)` and `faceAngle(lon)`. In the owner's "X, Y, Z" axes (as in Blender, Z up): **X** = pitch, **Y** = roll (removed), **Z** = spin about the globe's axis.
- **Zoom and rotation limits are coupled:** the window the screen sees on the globe has half-angle `asin(min(w,h)/2 / (radius_px · zoom))`: at zoom 2.6 on a 769 px-tall screen that is ~29°, so `maxOff()` drops from 45° to ~16° and the "upright" orientation (pitch `TILT`) may have no vehicle in view; `uprightTarget()` then falls to the nearest allowed view (`toward`). With `windowFraction` 0.8 the vehicles ended up almost at the bottom edge; 0.55 leaves them well inside. To test: scroll up 10 steps over the globe.
- **Straightening on release:** the "upright" orientation is `Rx(TILT)·Ry(a)`; its centre is always at latitude `TILT` (≈ 28.6°) and longitude `l` with `a = faceAngle(l)`. `upright()` takes the current centre's longitude and looks for the nearest one with a vehicle (`showsVehicle`, a 1° sweep).
- The spin towards the vehicle (`settle`) is measured in simulation time (`dt` ≤ 0.05 s): at low fps it takes much longer in real time. Wait several seconds before capturing. To test the drag: `left_click_drag` over the sphere. To see the limit in the browser, wait ~40 s for the automatic spin to leave an empty face on the Moon and then grab the globe.
- The floating card stores the selected vehicle in the **hash** and reads it **after mounting** (when coming back from the scene Next updates the URL after the first render).
- `VehicleCard` draws the procedural vehicle in an orthographic mini `<Canvas>` (`VehicleView`): it downloads nothing. The vehicles use a **fixed light in world space** (`SUN` in `lib/vehicles/kit.ts`), so the tones change as they turn.

## Mixed line endings and patching

- **CRLF/LF mixed:** several files (`themes.ts`, `Globe.tsx`, `Scene.tsx`, `CheckpointCard.tsx`, `globals.css`, `Hud.tsx`…) are CRLF and others LF. Multi-line `str.replace` patches fail on the CRLF ones: normalise to `\n` in memory and write back with the same ending (`split("\r\n").join("\n")`). Git warns "LF will be replaced by CRLF"; it is harmless.
- **Patching from the shell:** the quotes/escapes of `node -e` and `sed` with a regex break text with `\` or line breaks. Write the script to a file (the Write tool) and run it. Multi-line heredocs with quotes also failed in the tool's shell.

## Performance

- There is no per-frame raycast: everything uses `heightAt` over the grid.
- The minimap's bake (blur + contours) takes a few tens of ms; it happens on load and on a mission change.
- Possible shadow flicker when moving (the light's frustum follows the vehicle without snapping to the texel). See [roadmap.md](roadmap.md).

## Mobile and sizes

- **Testing a size:** `resize_window` does not change a maximised window. Open a 404 route (`/zz`), replace the `body` with an `<iframe style="width:390px;height:760px">` and drive it with `iframe.contentDocument` (the iframe's own `@media` and `innerWidth` apply). Pass `zoom` a region that contains the iframe. Reloading many WebGL iframes **kills the tab** ("This page couldn't load"): close and open another.
- **The globe turned with the wheel but not with a finger:** `PointerEvent.movementX` is 0 on touch; the drag uses the difference in `clientX/Y` between events.
